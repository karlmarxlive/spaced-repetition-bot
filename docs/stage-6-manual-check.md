# Полная ручная проверка этапа 6

Инструкция соответствует `roadmap.md` и текущей реализации этапа 6. Команды рассчитаны на Windows PowerShell и уже установленное окружение `.venv` с Python 3.14 и зависимостями из `requirements.txt`.

Проверку проводит человек. Команды запуска бота и планировщика ниже действительно отправляют сообщения Telegram. Используйте отдельного тестового бота и собственные тестовые аккаунты. Автономные тесты в конце инструкции используют подменённый транспорт.

## 1. Изолировать данные проверки

Рабочие `db.sqlite3`, `.env` и `media/` менять не нужно. Создайте временные настройки, отдельную SQLite и каталог файлов. Исходный код при этом используется из текущего проекта, вместе с последними исправлениями.

В первом терминале:

```powershell
Set-Location D:\projects\spaced-repetition-bot
$stage6Root = Join-Path $env:TEMP ('stage6-manual-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $stage6Root | Out-Null
$env:STAGE6_MANUAL_ROOT = $stage6Root
$env:PYTHONPATH = $stage6Root
$env:DJANGO_SETTINGS_MODULE = 'stage6_manual_settings'
$env:TELEGRAM_BOT_TOKEN = ''
$env:TELEGRAM_BOT_USERNAME = ''
$env:DJANGO_DEBUG = 'true'
$env:DJANGO_ALLOWED_HOSTS = 'localhost,127.0.0.1,testserver'
$env:DJANGO_SECRET_KEY = 'local-stage6-manual-check-only'

@'
import os
from pathlib import Path
from config.settings import *

_manual_root = Path(os.environ['STAGE6_MANUAL_ROOT'])
DATABASES = {'default': {'ENGINE': 'django.db.backends.sqlite3',
                         'NAME': _manual_root / 'manual.sqlite3'}}
MEDIA_ROOT = _manual_root / 'media'
STATIC_ROOT = _manual_root / 'staticfiles'
'@ | Set-Content -Encoding utf8 (Join-Path $stage6Root 'stage6_manual_settings.py')

$stage6Root
```

Сохраните выведенный путь: он понадобится в остальных терминалах. Пустые переменные Telegram здесь предотвращают использование рабочего токена из `.env`.

Проверьте путь базы **до миграций**:

```powershell
.\.venv\Scripts\python.exe manage.py shell -c "from django.conf import settings; print(settings.DATABASES['default']['NAME']); print(settings.MEDIA_ROOT)"
```

Оба пути должны находиться в созданном временном каталоге. Если видите рабочий `db.sqlite3` или `media/`, остановитесь и исправьте переменные окружения.

Подготовьте тестовую базу:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py migrate --check
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py createsuperuser
```

Каждая команда должна завершиться успешно. Учётная запись учителя создаётся только в тестовой базе.

## 2. Запустить три процесса

Во втором и третьем терминалах выполните общий блок. Подставьте сохранённый путь и имя отдельного тестового бота без `@`:

```powershell
Set-Location D:\projects\spaced-repetition-bot
$env:STAGE6_MANUAL_ROOT = 'C:\Users\ВАШЕ_ИМЯ\AppData\Local\Temp\stage6-manual-ДАТА-ВРЕМЯ'
$env:PYTHONPATH = $env:STAGE6_MANUAL_ROOT
$env:DJANGO_SETTINGS_MODULE = 'stage6_manual_settings'
$env:DJANGO_DEBUG = 'true'
$env:DJANGO_ALLOWED_HOSTS = 'localhost,127.0.0.1,testserver'
$env:DJANGO_SECRET_KEY = 'local-stage6-manual-check-only'
$env:TELEGRAM_BOT_USERNAME = 'ИмяТестовогоБота'
$stage6Credential = [System.Management.Automation.PSCredential]::new(
    'test-bot', (Read-Host 'Токен тестового бота' -AsSecureString))
$env:TELEGRAM_BOT_TOKEN = $stage6Credential.GetNetworkCredential().Password
Remove-Variable stage6Credential
```

Токен вводится локально без отображения. `.env` не редактируется. В каждом терминале ещё раз проверьте путь БД командой из раздела 1.

В первом терминале задайте такое же `TELEGRAM_BOT_USERNAME` — токен панели не требуется. Затем запустите:

```powershell
$env:TELEGRAM_BOT_USERNAME = 'ИмяТестовогоБота'
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Во втором терминале:

```powershell
.\.venv\Scripts\python.exe -m bot
```

Третий терминал пока оставьте свободным. Планировщик запускайте в указанных ниже сценариях:

```powershell
.\.venv\Scripts\python.exe manage.py run_scheduler
```

Он делает первый проход сразу, последующие — каждые 30 секунд. Остановка — `Ctrl+C`. Один проход без ожидания:

```powershell
.\.venv\Scripts\python.exe manage.py run_scheduler --once
```

`--once` также отправляет настоящие сообщения. Для удобства ручного контроля не запускайте одновременно постоянный планировщик и `--once`.

Откройте http://127.0.0.1:8000/admin/ и войдите под тестовым superuser. Одновременно должен работать только один polling-процесс для этого тестового токена.

## 3. Подготовить тестовые материалы и учеников

Создайте курс `Приёмка этапа 6` и темы в таком порядке:

| Тема | Порядок | Задания |
|---|---:|---|
| A | 10 | A1: условие `Вопрос A1`, ответ `11`; A2: `Вопрос A2`, ответ `12` |
| B | 20 | B1: `Вопрос B1`, ответ `22` |
| C | 30 | C1: `Вопрос C1`, ответ `33` |
| Пустая | 40 | Нет активных заданий |
| Отмена | 50 | O1: `Вопрос для отмены`, ответ `44` |
| Последняя | 60 | L1: `Последний вопрос`, ответ `55` |

Активируйте все задания, кроме заданий пустой темы. Для A1 установите порядок меньше A2. К A1 прикрепите два небольших тестовых файла, например картинку и текстовый файл. Они должны сохраниться в тестовом `MEDIA_ROOT`.

Создайте приглашение на тестовый курс. Откройте его своим тестовым Telegram-аккаунтом в личном чате, нажмите «Начать» и убедитесь, что ученик появился в админке.

Для нескольких независимых сценариев удобно иметь второй аккаунт. При одном аккаунте перед следующим сценарием снимайте **все** назначения, сохраняйте, затем включайте нужные темы. Это сбрасывает расписание и курсоры включаемых тем, но сохраняет историю. Само по себе это **не удаляет сегодняшнюю отметку ежедневной выдачи**.

Важно для планирования сценариев: ежедневная выдача учитывается для каждого зарегистрированного ученика, даже если у него нет назначений. Новый тестовый ученик должен регистрироваться при остановленном планировщике, а его темы — назначаться до нужного прохода.

Независимые сценарии ежедневной выдачи в один день запускайте на новой тестовой базе либо с новым, ещё не обработанным учеником. Не удаляйте вручную `DailyReviewRun`, очередь и попытки: это изменит проверяемые условия.

## 4. Наблюдать состояние без его изменения

Очередь, попытки и прогресс ещё не имеют отдельной статистики в админке этапа 6. Для проверки внутренних критериев используйте четвертый терминал с теми же настройками тестовой БД; токен в нём можно оставить пустым.

Создайте во временном каталоге файл наблюдения:

```powershell
@'
from modules.users.models import Student
from modules.repetitions.models import TopicProgress
from modules.study_sessions.models import StudySession, Attempt, ReviewQueueItem, DailyReviewRun

student = Student.objects.get(telegram_id=TELEGRAM_ID)
print('Ученик:', student.pk)
for title, rows in (
    ('Сессии', StudySession.objects.filter(student=student).order_by('pk').values(
        'id', 'state', 'started_at', 'finished_at', 'skipped')),
    ('Попытки', Attempt.objects.filter(student=student).order_by('pk').values(
        'id', 'session_id', 'topic_title', 'status', 'opened_at', 'finished_at')),
    ('Очередь', ReviewQueueItem.objects.filter(assignment__student=student).order_by('pk').values(
        'id', 'session_id', 'assignment_id', 'state', 'attempt_id')),
    ('Прогресс', TopicProgress.objects.filter(assignment__student=student).order_by('pk').values(
        'assignment__topic__title', 'interval_step', 'next_review_date')),
    ('Выдачи', DailyReviewRun.objects.filter(student=student).order_by('local_date').values(
        'local_date', 'formed_at')),
):
    print('\n' + title)
    for row in rows:
        print(row)
'@ | Set-Content -Encoding utf8 (Join-Path $env:STAGE6_MANUAL_ROOT 'inspect_stage6.py')
```

Замените `TELEGRAM_ID` в этом временном файле числом из карточки ученика. Запускайте после контрольных действий:

```powershell
.\.venv\Scripts\python.exe manage.py shell -c "import os; from pathlib import Path; exec((Path(os.environ['STAGE6_MANUAL_ROOT']) / 'inspect_stage6.py').read_text(encoding='utf-8-sig'))"
```

Скрипт только читает данные. Сохраняйте вывод до и после важных действий. В каждый момент должно быть не более одной открытой сессии и одной открытой попытки ученика. У одного назначения темы — не более одного элемента очереди в состояниях `pending`/`open`. Исторические элементы `done`, `skipped`, `cancelled` при этом сохраняются.

## 5. Основная ежедневная выдача и обычное завершение

Предусловия: новая база/необработанный сегодня ученик; назначены A и B; нет открытых попыток; планировщик остановлен. Проводите проверку вдали от московской полуночи.

1. В админке откройте «Настройка ежедневной выдачи». Убедитесь, что начальное время — 18:00, запись одна, удалить её или добавить вторую нельзя.
2. Задайте время на 2–3 минуты позже текущего московского времени.
3. Запустите постоянный планировщик. До назначенного времени сообщения приходить не должны. В наблюдении нет сегодняшнего `DailyReviewRun` и новой очереди этого ученика.
4. Дождитесь назначенного времени и следующего прохода, обычно не более 30 секунд после него.
5. Должны прийти тема A, условие A1 и оба вложения. B пока не отправляется.
6. Проверьте: одна сегодняшняя отметка, два элемента очереди, один `open`, один `pending`, одна открытая попытка.
7. Не отвечайте 60–90 секунд. Новых сообщений не должно быть; ID попытки и размеры очереди неизменны.
8. Ответьте `11`: сначала «Верно.», затем вопрос B1. По A ступень становится 1, следующая дата — завтра по Москве.
9. Ответьте `wrong`: сначала «Неверно.», затем итог `Ответов: 2; верных: 1; неверных: 1`. Эталон B1 бот не раскрывает.
10. По B ступень 0, следующая дата — завтра по Москве. Сессия `finished`, обе попытки завершены, открытых вопросов нет.
11. Подождите ещё два прохода. Новых вопросов и второго итога быть не должно.

Для каждого ответа расписание отсчитывается от **московской календарной даты ответа**, а не от даты открытия вопроса.

## 6. Ручной запуск до времени выдачи

Предусловия: независимый необработанный сегодня ученик с A и B; время выдачи впереди.

1. Выполните `/review` до установленного времени. Получите A1 и вложения сразу.
2. Повторите `/review`: приходит то же открытое задание; новая попытка не создаётся.
3. Оставьте A1 без ответа и дождитесь ежедневного прохода.
4. Планировщик создаёт сегодняшнюю отметку, но не отправляет A1 повторно и не добавляет второй элемент A или B.
5. Ответьте A1 и B1. Итог относится к той же сессии; пустого дополнительного занятия нет.

Повтор вопроса по явной команде `/review` ожидаем. Автоматического повтора от планировщика быть не должно.

## 7. Изменение времени без перезапуска

Предусловия: новый необработанный ученик с A; время первоначально впереди; постоянный планировщик работает.

1. Установите время на несколько минут позже текущего московского времени. Убедитесь, что выдачи пока нет.
2. Перенесите время на одну минуту раньше текущего. Не перезапускайте планировщик.
3. На ближайшем проходе ученик получает A1. Появляется одна сегодняшняя отметка.
4. После этого меняйте время вперёд и назад, каждый раз дожидаясь прохода.
5. Сегодня повторной автоматической отправки не будет. Отметка остаётся одна, очередь не дублируется.
6. Попробуйте сохранить `25:00`: админка должна показать ошибку и сохранить прежнее значение.

Изменение времени не сбрасывает уже обработанную московскую дату.

## 8. Пустая выдача и тема без активных заданий

Проверьте на двух независимых новых учениках или двух свежих тестовых базах.

**Нет назначенных тем:**

1. Зарегистрируйте ученика, не назначайте темы. Задайте уже наступившее время.
2. Запустите `run_scheduler --once` дважды.
3. Сообщений нет. Есть одна сегодняшняя отметка; нет открытой попытки и живой очереди. Допустима завершённая пустая сессия автоматического формирования.
4. Выполните `/review`: ручная команда должна явно сообщить, что заданий сейчас нет.

**Назначена только «Пустая»:**

1. Назначьте тему без активных заданий до первого ежедневного прохода.
2. Запустите два прохода. Сообщений нет, в том числе уведомления о пропуске и итог не отправляются автоматически.
3. Есть одна сегодняшняя отметка; элемент очереди `skipped`, прогресс не изменён.
4. Выполните `/review`: вручную доступны уведомление о пропуске и итог с количеством пропущенных тем.

Завершённая пустая сессия при самостоятельной пустой выдаче допустима; при этом автоматических сообщений быть не должно.

## 9. Позднее назначение темы

Предусловия: ежедневная выдача с A уже состоялась; A1 открыт.

1. Назначьте B после сегодняшней выдачи, оставляя A включённой.
2. Дождитесь двух проходов: сообщения нет, B не добавляется в сегодняшнюю автоматическую очередь.
3. Ответьте A1: занятие заканчивается без B1.
4. Выполните `/review`: B1 становится доступен сразу, сегодня.
5. Для отдельной проверки автоматического пути повторите условия на другом ученике и **не** вызывайте `/review`. B должна добавиться на следующей московской дате после времени выдачи.

Не совмещайте ручную и автоматическую ветви на одной уже отвеченной B: после ручного ответа её следующий срок будет рассчитан заново.

## 10. Перезапуск и простой планировщика

**Перезапуск при открытом вопросе:**

1. Получите A1 через ежедневную выдачу, не отвечайте. Запишите ID попытки.
2. Остановите бот и планировщик, затем запустите их снова с той же тестовой БД.
3. Планировщик не отправляет A1 заново. Сегодняшняя отметка и очередь сохранены.
4. Выполните `/review`: возвращается A1 с тем же ID попытки и вложениями.
5. Ответьте: сохранённая очередь продолжается.

**Первый запуск после времени выдачи:**

1. На новом необработанном ученике назначьте A и B, установите время в ближайшем будущем.
2. Держите планировщик выключенным до прохождения этого времени.
3. Запустите его после времени выдачи. Первый проход сразу формирует очередь и отправляет A1.
4. Очередь содержит по одному элементу A и B; повторный проход молчит.

**Запуск до времени выдачи:** на другом новом ученике запустите планировщик заранее. Он должен ждать заданного времени, даже если темы уже доступны для `/review`.

## 11. Затянувшееся занятие и следующий московский день

Эта ручная проверка требует перехода календарной даты. Не меняйте системные часы. Ускоренное воспроизведение без ожидания приведено в разделе 15.

1. В день D назначьте A и B, получите автоматическую выдачу после её времени.
2. Ответьте A1 верно. B1 оставьте открытым до следующего дня.
3. По A следующая дата — D+1. Зафиксируйте ID B1 и состояние очереди.
4. В день D+1 после времени выдачи дождитесь планировщика.
5. B1 повторно не отправляется. Появляется отметка D+1 и один ожидающий элемент A, поскольку её новый срок наступил.
6. Запустите ещё несколько проходов: дополнительного элемента A нет, открытой остаётся только B1.
7. Ответьте B1 верно. Дата её следующего повторения — D+2, от даты ответа.
8. Получите A2: круговой выбор продвинулся после A1. Это новая попытка A в той же длительной сессии.
9. Ответьте A2 верно. Итог всей сессии: три ответа, три верных.
10. По A ступень 2, следующий срок — через три дня от последнего ответа. По B ступень 1, следующий срок — через один день.

Для нескольких пропущенных дней оставьте B1 открытым дольше. При запуске после времени выдачи должна добавиться только одна просроченная A, без отдельных заданий за каждый пропущенный день. Отметки за выключенные дни задним числом не создаются.

Для проверки московской даты сравнивайте `DailyReviewRun.local_date` с датой в Москве, особенно около полуночи: московская дата может отличаться от UTC. Время 00:00 означает, что выдача может сформироваться уже на первом проходе нового московского дня.

## 12. Отмена, повторное включение и суммарный итог

Остановите планировщик. Для ученика сбросьте назначения и включите A, B, «Пустая», «Отмена», «Последняя».

1. Вызовите `/review`, ответьте A1 верно, B1 неверно.
2. Бот сообщает о пропуске «Пустая» и открывает O1.
3. В карточке ученика отключите «Отмена». Остальные назначения сохраняйте.
4. Отправьте запоздалый ответ на O1. Он не засчитывается; бот сообщает об отмене и открывает L1.
5. Ответьте L1 верно.
6. Итог: `Ответов: 3; верных: 2; неверных: 1. Пропущено тем: 1; отменено: 1.`
7. В истории одна отменённая попытка O1 без введённого принятого ответа. Прогресс отменённой и пропущенной темы не меняется вследствие отмены/пропуска.
8. Повторно включите «Отмена» и вызовите `/review`. Выдача начинается заново; историческая отменённая попытка сохранена.

Дополнительно: при открытой A1 отключите ожидающую B. Её очередь должна стать `cancelled`, B1 не отправляется, попытка B не создаётся. В текущем кратком итоге «отменено» считает отменённые **открытые попытки**; снятое ожидающее назначение видно в очереди, но отдельным ответом или ошибкой ученика не считается.

Повторное включение сбрасывает расписание и курсор темы; история попыток сохраняется.

## 13. Команды, снимки задания и вложения

При открытом вопросе:

1. Отправьте `/unknown`, фото/документ с подписью, голосовое сообщение. Бот объясняет допустимый формат; попытка остаётся открытой, прогресс не меняется.
2. Отправьте `/start`: регистрация не создаёт дубликата, открытый вопрос сохраняется.
3. Измените условие и эталон открытого задания в админке. `/review` возвращает исходный снимок условия; ответ проверяется по исходному эталону.
4. Деактивируйте открытое задание в банке: текущая попытка остаётся доступной. Деактивация задания и отключение назначения темы — разные действия.
5. Убедитесь, что при выдаче большого условия текст приходит целиком, без обрезки, затем вложения в сохранённом порядке.
6. Проверьте ответы с пробелами по краям: они удаляются при сравнении. Регистр, внутренние пробелы и формат числа автоматически не преобразуются.

После изменения банка восстановите тестовые данные перед проверкой кругового выбора A1 → A2.

## 14. Сбой доставки и восстановление через /review

Проверяйте на отдельном тестовом аккаунте/боте. Не удаляйте рабочие вложения и не отключайте сеть, от которой зависит текущая рабочая сессия.

Воспроизводимый вариант:

1. Зарегистрируйте нового ученика и назначьте A. Затем заблокируйте тестового бота в Telegram до первой ежедневной выдачи этому ученику.
2. Запустите один проход после времени выдачи. В консоли появляется ошибка доставки; проход завершается без аварийного завершения всего планировщика.
3. Попытка A1 и сегодняшняя отметка уже сохранены. Следующий проход не повторяет отправку.
4. Разблокируйте бота и отправьте `/review`. Приходит сохранённое A1, новая попытка не создаётся.
5. Ответьте и завершите занятие.
6. При наличии второго ученика, зарегистрированного и назначенного до прохода, проверьте, что ошибка отправки первому не мешает выдаче второму.

Отсутствие автоматического повтора после ошибки — текущее поведение этапа 6. Outbox, гарантированная доставка, дедупликация Telegram-событий и автоматические повторы относятся к этапу 7.

## 15. Ускоренные проверки без ожидания следующего дня

Ускоренная демонстрация нескольких дней на временной файловой SQLite:

```powershell
.\.venv\Scripts\python.exe -m tests.daily_reviews_demo
```

Ожидается завершение с `Stage 6 offline demo: OK`. Демонстрация показывает границу 18:00, отсутствие повторной выдачи, сохранность после открытия БД заново и три ответа в длительной сессии за два дня. Сетевых отправок нет.

Для проверки пропущенных дней, московской даты, отсутствия дубликатов и конкурентной работы запустите весь набор. Он включает проверки на отдельной файловой SQLite:

```powershell
.\.venv\Scripts\python.exe manage.py test --verbosity 2
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run --settings=config.test_settings
.\.venv\Scripts\python.exe manage.py migrate --check
.\.venv\Scripts\python.exe manage.py check
```

`manage.py test` самостоятельно выбирает `config.test_settings`: рабочая и ручная тестовая базы не используются. `makemigrations` выше тоже явно использует автономные настройки. Последние две команды проверяют подготовленную ручную тестовую установку.

При подготовке этой инструкции полный набор содержал 127 успешно прошедших тестов; ожидаемый смысл результата — `OK`, отсутствие изменений моделей для миграций и отсутствие неприменённых миграций.

## 16. Зафиксировать результат и завершить проверку

Для каждого сценария записывайте:

| Поле | Что зафиксировать |
|---|---|
| Версия | Commit и наличие локальных изменений |
| Ученик | Telegram ID тестового аккаунта |
| Время | Московская дата и настройка выдачи |
| Предусловия | Назначения, сегодняшняя отметка, открытый вопрос |
| Действия | Команды, ответы, изменения админки, перезапуски |
| Telegram | Порядок и количество сообщений, итог |
| База | ID сессии/попыток, состояния очереди, прогресс до/после |
| Результат | Пройдено / ошибка / не выполнялось |

Этап 6 проходит приёмку, если выполняются все проверенные критерии: одна выдача на московскую дату, одна открытая попытка, отсутствие дубликатов живой очереди, сохранность после перезапуска, тишина пустой автоматической выдачи, отсутствие автоматических повторов открытого вопроса, правильное продолжение и итог, правильные даты прогресса.

Если многодневные сценарии проверены только ускоренными тестами, отметьте это прямо: реальное ожидание следующего дня вручную не выполнялось. Аналогично прохождение автономных тестов не подтверждает доставку настоящих сообщений и вложений.

Остановите все три процесса через `Ctrl+C`. Не переносите тестовую SQLite и файлы в рабочую установку. Сохраните отчёт и нужные снимки состояния; временный каталог после этого можно удалить. Закрытие тестовых PowerShell-терминалов уберёт заданные в них переменные окружения.
