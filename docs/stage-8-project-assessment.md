# Этап 8 — подготовка серверной сборки

Дата: 6 октября 2026 года. Реализованы код и эксплуатационная инструкция. Docker-сборка и проверки внутри точного Linux-образа выполнены успешно. Развёртывание на Amvera не выполнялось.

## Реализация

- Dockerfile, `.dockerignore`, `amvera.yml`: Python 3.14.6-slim-bookworm закреплён digest, весь набор Python-пакетов закреплён; исключены секреты, локальные данные, архивы, Git и окружения. Тег/digest подтверждены через официальный Docker Registry API, HTTP 200.
- `config.production`: обязательный SECRET_KEY, DEBUG=false, конкретные hosts и HTTPS CSRF origins, secure cookies/HSTS, отдельное включение доверия ingress, постоянные абсолютные пути базы/media. Сервер не читает локальный `.env`.
- Gunicorn, WhiteNoise, build-only настройки для collectstatic без базы и runtime-секретов. Вложения сохраняют защищённую выдачу через админку.
- Supervisor: setup/run, единственный владелец хранилища через flock, миграции и check --deploy до запуска компонентов, отказ всей группы при завершении компонента, SIGTERM/SIGINT и ограниченная остановка потомков.
- В setup работает только панель; учитель создаётся интерактивным `createsuperuser`. В run требуются учитель, токен и успешный внешний экспорт резервной копии.
- Готовность и liveness, активность получения Telegram updates и планировщика, длительные ошибки событий/выдачи, возраст и объём outbox, окончательные ошибки доставки, свежесть копии. Логи идут в консоль с редактированием секретов.
- Полный останов записи при резервировании, SQLite Backup API + media, integrity check, SHA-256 manifest/revision, ежедневный запуск, локальная ротация, подключаемый внешний экспорт и пример HTTPS PUT adapter. Восстановление в пустые назначения, без Telegram.
- SQLite IMMEDIATE для серверных транзакций с ожиданием 20 секунд: админка получает writer lock до чтения формы и не пытается повысить deferred read lock при конкурентном ответе/выдаче.
- Миграция `delivery.0002` добавляет `created_at` для контроля возраста outbox. Защита обратной миграции отказывает до удаления поля при наличии истории: неудачный откат всей delivery-схемы сохраняет применённой последнюю миграцию.

## Повторная проверка Docker

Docker Engine 29.8.2 установлен системно в Ubuntu 24.04 WSL из официального apt-репозитория Docker. Docker, docker.socket и containerd имеют состояние автозапуска `disabled`; службу Docker запустили вручную для проверки. Пользователь nsfro не добавлен в группу docker. Административные команды выполнялись штатным запуском WSL от root.

Выполнен [deploy/check_docker.sh](../deploy/check_docker.sh): hello-world, сборка образа `spaced-repetition:stage8`, pip check, полный набор тестов, проверка миграций, production smoke, создание отдельного тома, остановка и удаление контейнера, новый контейнер на том же томе, затем восстановление архива в ещё один том. Оба контейнера завершились по SIGTERM с кодом 0. Исходный и восстановленный снимки сравнивались по всем полям Attempt, StudySession, ReviewQueueItem, OutgoingMessage и TopicProgress, дополнительно проверены курс, учитель через readiness и содержимое файла media. Тестовые контейнеры и тома удалены; образ оставлен для следующих проверок.

## Ещё требуется до развёртывания

Полный рабочий стек с реальным Telegram, суточное расписание, память трёх процессов, настоящий внешний storage и восстановление полного учебного банка подлежат приёмке следующих этапов.

На Amvera подтвердить overwrite proxy-заголовков, HTTPS без циклов, Host для проб, поддержку flock постоянным хранилищем и остановку старого polling до обновления. Конкретный домен, тариф, экспортёр и удалённая политика хранения не выбраны. Это параметры запуска, а не сведения, которые можно подтвердить автономным тестом.
