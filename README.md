# Spaced Repetition Bot

Telegram-бот для подготовки к ЕГЭ по информатике с интервальными повторениями. Помогает ученикам регулярно возвращаться к пройденным темам, а учителю — управлять заданиями и следить за прогрессом через веб-панель.

Учитель наполняет банк заданий и отмечает изученные темы. Бот подбирает задания, проверяет короткие ответы и назначает следующий повтор с учётом результата. Ученику достаточно личного чата в Telegram.

## Возможности

- **Банк заданий:** курсы, темы, текстовые условия, эталоны ответов и файловые вложения.
- **Регистрация по приглашению:** одноразовая ссылка от учителя привязывает ученика к выбранному курсу.
- **Персональное расписание:** повторяются только назначенные ученику темы, для которых наступила дата повторения.
- **Занятия в Telegram:** ежедневная выдача по расписанию или ручной запуск командой `/review`.
- **Автоматическая проверка:** результат после каждого ответа и итог занятия.
- **Панель учителя:** назначения тем, прогресс, история попыток и состояние доставки по каждому ученику.
- **Сохранение учебного состояния:** очередь заданий и открытая попытка сохраняются между перезапусками; повторная обработка события не приводит к повторному зачёту ответа.

## Как устроено повторение

Прогресс ведётся отдельно по каждой назначенной теме. При последовательных верных ответах интервалы растут: **1 → 3 → 7 → 14 → 30 → 60 дней**. После достижения последней ступени повторение продолжается каждые 60 дней. Ошибка сбрасывает ступень и назначает повтор на следующий день.

Расписание использует календарные дни по московскому времени. Время ежедневной выдачи задаётся в панели учителя; по умолчанию — **18:00**. Команда `/review` позволяет начать или продолжить занятие вручную. Задания внутри темы выдаются по порядку, циклически.

Ответ сравнивается с эталоном после удаления пробелов по краям. Регистр, внутренние пробелы и формат записи имеют значение. Это проверка короткого текстового ответа; решения в виде программ или файлов автоматически не проверяются.

## Технологии

**Python 3.14 · Django 5.2 · aiogram 3 · SQLite**

Проект построен как модульный монолит с общей базой данных. Панель учителя работает через Django Admin, бот получает сообщения через Telegram long polling, отдельный планировщик отвечает за ежедневную выдачу и повторы отправки. Серверная сборка использует Docker, Gunicorn и WhiteNoise.

Зависимости с закреплёнными версиями находятся в [requirements.txt](requirements.txt).

## Локальная установка

Понадобятся Python 3.14 и бот, созданный через `@BotFather` в Telegram. SQLite входит в стандартную библиотеку Python. Команды ниже выполняются из корня клонированного репозитория.

### 1. Установите зависимости

**Windows / PowerShell:**

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

**Linux / WSL:**

```bash
python3.14 -m venv .venv-wsl
.venv-wsl/bin/python -m pip install -r requirements.txt
```

В WSL используйте отдельное Linux-окружение: Windows-окружение `.venv` для него не подходит. Активация окружения не требуется — команды используют его Python напрямую.

### 2. Настройте окружение

Создайте `.env` из [.env.example](.env.example), если файл ещё не существует.

**Windows / PowerShell:**

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

**Linux / WSL:**

```bash
if [ ! -f .env ]; then cp .env.example .env; fi
```

Откройте `.env` в редакторе и заполните параметры:

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен от BotFather. Обязателен для бота и планировщика. |
| `TELEGRAM_BOT_USERNAME` | Имя того же бота без `@`. Нужно для формирования ссылок-приглашений в панели. |
| `DJANGO_SECRET_KEY` | Случайная секретная строка; замените значение из примера. |
| `DJANGO_DEBUG` | `true` для локальной разработки; на сервере — `false`. |
| `DJANGO_ALLOWED_HOSTS` | Разрешённые хосты через запятую. Для локального запуска подходят значения из примера. |

Не публикуйте `.env` и токены. Переменные окружения процесса имеют приоритет над `.env`; после изменения настроек перезапустите приложение.

### 3. Подготовьте базу и учётную запись учителя

Для новой установки:

**Windows / PowerShell:**

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser
```

**Linux / WSL:**

```bash
.venv-wsl/bin/python manage.py migrate
.venv-wsl/bin/python manage.py createsuperuser
```

Учитель входит в панель под созданной учётной записью Django. Ученики регистрируются через Telegram и не получают доступа к панели.

При обновлении существующей установки сначала остановите процессы и сделайте согласованную резервную копию SQLite и `media/`. Существующего учителя повторно создавать не нужно. Подробнее — в [инструкции по эксплуатации](docs/amvera-operations.md).

### 4. Запустите приложение

**Windows / PowerShell:**

```powershell
.\.venv\Scripts\python.exe run_dev.py
```

**Linux / WSL:**

```bash
.venv-wsl/bin/python run_dev.py
```

Скрипт проверит зависимости и наличие применённых миграций, затем запустит панель, бота и планировщик. Откройте [панель учителя](http://127.0.0.1:8000/admin/). Для другого порта добавьте `--port 8001`.

Логи выводятся в терминал. **Ctrl+C** останавливает все три процесса. После изменения кода запуск нужно повторить: автоматическая перезагрузка отключена.

Для одного Telegram-токена должен работать только один polling-процесс; планировщик тоже запускается в одном экземпляре. Перед локальным запуском убедитесь, что этот токен не используется работающим ботом на сервере.

При необходимости компоненты можно запускать отдельно, каждый в своём терминале:

| Компонент | Команда после пути к Python своего окружения |
| --- | --- |
| Панель учителя | `manage.py runserver 127.0.0.1:8000` |
| Telegram-бот | `-m bot` |
| Планировщик | `manage.py run_scheduler` |

Панель можно использовать без Telegram-токена. Для автоматической выдачи и обработки ответов нужны одновременно работающие бот и планировщик.

## Первое занятие

1. В панели создайте курс, его темы и задания. У активного задания должны быть заполнены условие и эталон ответа; при необходимости добавьте вложения.
2. Создайте приглашение на курс, сохраните его и передайте ссылку ученику.
3. Ученик открывает ссылку в личном чате с ботом и нажимает «Начать».
4. В карточке ученика отметьте пройденные темы — они попадут в расписание повторений.
5. Ученик отправляет `/review` или дожидается ежедневной выдачи, отвечает текстом и получает результат. Для однозначной привязки ответа к заданию можно использовать Telegram «Ответить» на сообщение с вопросом.
6. В карточке ученика откройте «Прогресс, история и доставка», чтобы посмотреть результаты и даты следующих повторений.

Учебные материалы заполняет учитель через панель.

### Команды бота

| Команда | Действие |
| --- | --- |
| `/start` | Регистрация при переходе по приглашению или приветствие для зарегистрированного ученика. Новому пользователю без приглашения бот предложит обратиться к учителю. |
| `/review` | Начать занятие по темам, готовым к повторению, или продолжить незавершённое. |

## Структура проекта

```text
bot/                     Обработчики сообщений и Telegram long polling
modules/
  materials/             Курсы, темы, задания и вложения
  users/                 Ученики, приглашения, назначения тем и статистика
  checking/              Проверка коротких ответов
  repetitions/           Прогресс и расчёт интервалов
  study_sessions/        Занятия, попытки и очередь заданий
  delivery/              Обработка событий и очередь исходящих сообщений
config/                  Настройки Django и правила повторения
deploy/                  Серверный запуск, резервирование и проверка состояния
tests/                   Автоматические проверки
docs/                    Документация
manage.py                Команды Django
run_dev.py               Совместный локальный запуск трёх процессов
```

## Проверки

**Linux / WSL:**

```bash
.venv-wsl/bin/python manage.py test
.venv-wsl/bin/python manage.py check --settings=config.test_settings
.venv-wsl/bin/python manage.py makemigrations --check --dry-run --settings=config.test_settings
```

В Windows замените `.venv-wsl/bin/python` на `.\.venv\Scripts\python.exe`.

`manage.py test` автоматически выбирает тестовые настройки. Проверки используют изолированные базы и временные каталоги вложений, не изменяют рабочие данные и не отправляют сообщения ученикам.

## Развёртывание и эксплуатация

В репозитории есть [Dockerfile](Dockerfile) и [конфигурация Amvera](amvera.yml). Серверная сборка хранит SQLite и вложения в постоянном каталоге `/data`. Управляющий процесс запускает компоненты приложения, выполняет резервирование и контролирует их состояние.

Порядок первого запуска, серверные переменные, настройка внешнего хранения резервных копий, обновление и восстановление описаны в [docs/amvera-operations.md](docs/amvera-operations.md).
