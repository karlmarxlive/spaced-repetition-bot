# Роадмап бота для подготовки к ЕГЭ по информатике

Строим проект небольшими законченными итерациями: у каждой есть рабочий результат и сценарий проверки. Базовый учебный цикл реализован на этапах 1–7. Следующий приоритет — подготовить его к Amvera, проверить реальную выдачу и ответы и запустить постоянную работу. ИИ-проверку и помощь в решении добавляем после запуска базовой версии.

План пересмотрен 6 октября 2026 года. Подробности: [подготовка и запуск на Amvera](docs/amvera-launch-plan.md). Это план работ; серверное развёртывание ещё не выполнено.

## Основа проекта

**Стек:** Python, Django со стандартной админ-панелью, SQLite, aiogram для Telegram. На этапах 6–7 локально работают три процесса: веб-панель, бот через long polling и планировщик ежедневной выдачи. Они используют одну базу данных.

**Архитектура:** модульный монолит — один проект с отдельными системами и явными интерфейсами между ними. Микросервисы, Redis, Celery и отдельный фронтенд на старте не нужны.

| Модуль | Ответственность |
|---|---|
| Пользователи | Учитель, ученики, приглашения и привязка Telegram |
| Учебный материал | Курс, темы, задания, эталонные ответы и вложения |
| Повторения | Прогресс по темам и расчёт следующей даты |
| Учебная сессия | Очередь заданий, текущий вопрос, обработка попыток |
| Проверка | Сначала сравнение с эталоном, позднее проверка через ИИ |
| Доставка | Отправка сообщений, повторные попытки при сбоях |
| Интерфейсы | Telegram для ученика, Django Admin для учителя |

Telegram-обработчики и формы админки вызывают общие прикладные операции. Правила повторения и проверки не размещаем непосредственно в обработчиках кнопок.

## Правила первой версии

- Один учитель, один курс, несколько учеников. Учитель входит в веб-панель; ученик регистрируется через приглашение в Telegram.
- Прогресс хранится отдельно для каждой пары **«ученик — тема»**. Учитель отмечает темы, которые ученик уже прошёл.
- При включении темы первое задание становится доступным в ближайшую ежедневную выдачу.
- За один цикл выдаётся по одному заданию на каждую тему, срок повторения которой наступил. В каждый момент у ученика только одно активное задание.
- После верных ответов интервалы составляют **1 → 3 → 7 → 14 → 30 → 60 → 60… дней** (согласовано 25.09.2026). Любая ошибка сбрасывает ступень на 0 и назначает повторение через **1 день**; следующий верный ответ даёт ступень 1 и **1 день**.
- Интервал отсчитывается от календарной даты принятого ответа в `Europe/Moscow`. Выдача начинается в заданное учителем время; первоначальное значение — **18:00**.
- Неверный ответ завершает попытку. Бот сообщает об ошибке, **не раскрывает эталон**, затем отправляет следующее задание.
- Если ученик не ответил, текущее задание сохраняется, расписание темы не меняется. Следующая ежедневная выдача не создаёт второе активное задание.
- Просроченные темы не накапливают отдельные задания за каждый пропущенный день: одна тема занимает одно место в очереди.
- Задания внутри темы проходят по кругу в устойчивом порядке. При единственном задании оно повторяется.
- Отключение темы прекращает её выдачу и отменяет незавершённое задание по ней. Повторное включение начинает цикл заново; история попыток сохраняется.

## Итерации разработки

### 1. Каркас и локальный запуск

**Сделать:** структуру модулей, настройки окружения, миграции, тестовый запуск Django и бота, журналирование ошибок. Секреты хранить вне репозитория, подготовить пример конфигурации и инструкцию запуска.

**Результат:** веб-панель открывается локально, бот отвечает на `/start`.

**Проверка:** проект запускается по инструкции с пустой базой; отсутствие токена вызывает понятную ошибку. Добавление данных не требуется для запуска тестов.

### 2. Курс и банк заданий

**Сделать:** модели курса, тем и заданий; управление ими через админку. Задание содержит текст условия, несколько необязательных вложений (картинок или файлов), эталон короткого ответа и признак активности. Вложения хранятся локально отдельными записями `TaskAttachment` и скачиваются через защищённый маршрут админки. Поддержка нескольких вложений реализована; миграция сохраняет прежние ссылки без перемещения файлов.

**Результат:** учитель может самостоятельно наполнить небольшой учебный банк.

**Проверка:** создать, отредактировать и отключить задание; проверить сохранение вложений. Не разрешать активировать задание без условия или ответа. Используемые задания архивировать, сохраняя историю.

### 3. Регистрация и пройденные темы

**Сделать:** одноразовые ссылки-приглашения, профиль ученика и отметки пройденных тем в админке. Telegram ID служит постоянным идентификатором; имя пользователя — только отображаемым полем.

**Результат:** ученик открывает приглашение, регистрируется, учитель назначает ему темы.

**Проверка:** повторный `/start` не создаёт дубликат; использованное приглашение нельзя применить для другого аккаунта; ученик не получает доступ к функциям учителя.

### 4. Движок интервального повторения

**Сделать:** прогресс темы, ступень интервала, дату следующего повторения и расчёт переходов. Передавать текущее время в расчёты и операции включения темы явно, чтобы тестировать месяцы обучения за секунды. `StudentTopic` остаётся единственным источником активности назначения; прогресс не содержит независимо изменяемого дубликата этого флага. Включение и сброс прогресса выполняются одной прикладной операцией; с появлением учебных сессий отключение также атомарно отменяет незавершённое задание.

**Результат:** расписание полностью работает без Telegram.

**Проверка:** вся последовательность до повторных 60 дней; ошибка на любой ступени; несколько ошибок подряд; независимость учеников и тем; ответы после полуночи; отключение и повторное включение темы.

### 5. Полный учебный цикл по команде

**Сделать:** команду `/review`, очередь наступивших тем, отправку условия со всеми вложениями, приём текстового ответа и автоматический переход к следующему заданию. После очереди — краткий итог занятия.

При открытии задания сохранять снимок условия и эталона для попытки. Деактивация задания или перенос его в другую тему влияют на последующую выдачу; открытая попытка продолжает использовать исходную тему и снимок. Отключение назначенной ученику темы отменяет её незавершённое задание согласно общим правилам.

Для коротких ответов удалять только пробелы по краям; затем сравнивать с эталоном точно. Регистр, внутренние пробелы и числовые форматы автоматически не преобразовывать.

**Результат:** основной сценарий уже можно пройти вручную от начала до конца.

**Проверка:** правильный и неправильный ответ, пустая очередь, тема без активных заданий, повторная команда во время вопроса. Команды и неподдерживаемые вложения не засчитываются как неправильный ответ.

### 6. Автоматическая ежедневная выдача

**Сделать:** общее время выдачи в админке, отдельный планировщик и сохранение очереди в базе. `/review` оставить для ручного запуска и продолжения.

Реализовано: единственная настройка времени в Django Admin (18:00, Europe/Moscow), команда `python manage.py run_scheduler`, постоянная очередь и отдельная отметка формирования выдачи для ученика и московской даты. После этапа 7 планировщик проверяет расписание и доставку при запуске и через 2 секунды после каждого прохода; смена времени подхватывается без перезапуска и не создаёт вторую выдачу за уже обработанную дату.

При открытом задании новые наступившие темы добавляются в очередь без дубликатов, без повторной отправки текущего вопроса и без напоминаний. После простоя компьютера планировщик подхватывает просроченные темы, когда запускается после заданного времени; отдельные вопросы за каждый пропущенный день не накапливаются. При пустой выдаче сообщения не отправляются.

Тема, включённая после состоявшейся ежедневной выдачи ученику, автоматически попадает в следующую; `/review` позволяет начать её сразу. После ответа бот продолжает сохранённую очередь. В затянувшемся занятии ранее отвеченная тема может получить новую попытку при наступлении следующего срока, но у ученика остаётся только одно открытое задание.

**Результат:** бот сам начинает повторение и продолжает его после ответов.

**Проверка:** наступление времени, повторный проход планировщика, пропущенный день, несколько просроченных тем, незавершённая предыдущая сессия. Тесты используют управляемое время вместо реального ожидания.

### 7. Надёжность и завершение базовой версии

**Статус:** реализован в коде. Транзакционный журнал Telegram updates и outbox, повторы и восстановление захватов, привязка ответов к доставленному вопросу, персональная история и прогресс в Django Admin. Автономные проверки описаны в README; реальная доставка и ручная приёмка по `docs/stage-7-manual-check.md` ещё требуют отдельного выполнения.

**Сделать:** расширить базовую атомарность попытки и расписания этапа 5 защитой от повторной обработки Telegram-событий, сохранением состояния исходящих сообщений и повторной отправкой при временных ошибках. Базовый запрет повторного завершения одной попытки уже обязателен на этапе 5.

В админке сделать подробную статистику **отдельно по каждому ученику**, доступную из его карточки:

- Назначенные и отключённые темы, текущая ступень повторения, соответствующий интервал и дата следующего повторения. «Закрытая тема» не означает окончание повторений: последняя ступень продолжает цикл.
- История выполненных заданий: исходная тема, сохранённые условие и эталон, введённый ответ, успешный/неуспешный результат, даты открытия и завершения. Отменённые и незавершённые попытки отображать отдельно, не считать ошибками ученика.
- Фильтры по теме, результату и периоду; персональное количество верных и неверных ответов.
- Текущее задание и ошибки доставки выбранного ученика.

**Общую статистику по всем ученикам не делать.** Историю и прогресс показывать только для чтения. Проверить сохранность снимков условия и эталона, введённых на этапе 5, при перезапуске и редактировании банка, а также отображение истории после отключения и повторного включения темы.

**Результат:** базовая локальная версия реализована; допуск к тестированию с учениками подтверждается ручной приёмкой на отдельной установке.

**Проверка:** перезапуск до и после ответа, временная потеря сети, блокировка бота учеником, быстрые повторные сообщения, изменение задания во время сессии. Повторная обработка не должна дважды менять прогресс.

При неопределённом результате отправки Telegram возможен повтор сообщения; он должен ссылаться на то же задание и не создавать новую попытку.

### 8. Подготовка базовой версии к Amvera

**Сделать:** Dockerfile, .dockerignore и amvera.yml; производственные настройки Django, Gunicorn и раздачу статических файлов; постоянные пути SQLite и media в /data. Подготовить запуск панели, единственного polling-процесса и единственного планировщика с обработкой SIGTERM и восстановлением после сбоя. Миграции выполнять один раз до запуска рабочих процессов после резервирования данных. Сохранить защищённую выдачу вложений через админку.

Первый запуск — один экземпляр приложения, SQLite и long polling. Redis, Celery, webhook и PostgreSQL не входят в этот этап. Проверку коротких ответов по эталону сохраняем; ИИ для работы первой версии не требуется.

**Результат:** воспроизводимая серверная сборка без зависимости от локального компьютера, с инструкцией настройки и обновления.

**Проверка:** сборка с закреплёнными зависимостями, автономные тесты, check --deploy с серверными настройками, миграции пустой базы и копии существующей, статические файлы при DEBUG=false, остановка/перезапуск всех процессов и сохранность данных после пересоздания контейнера. Проверить конкурентную работу админки, ответов и выдачи с SQLite.

### 9. Приёмка и первый запуск на Amvera

**Сделать:** пройти ручную приёмку на отдельном тестовом боте и базе; создать приложение Amvera, настроить секреты, HTTPS, хранилище и контроль состояния. После приёмки инициализировать чистую серверную базу, создать учителя и заполнить учебный банк; локальную базу и вложения не переносить. Первая группа — до 10 учеников. Перед запуском рабочего polling остановить локальный экземпляр. Проверить отсутствие одновременно работающих экземпляров при обновлении Amvera.

**Результат:** учитель управляет курсом через HTTPS, бот ежедневно выдаёт задания, принимает ответы и сохраняет расписание независимо от локального компьютера.

**Проверка:** приглашение, назначение темы, автоматическая выдача по московскому времени, верный/неверный ответ, итог, продолжение после перезапуска, реальные вложения, блокировка бота и восстановление, отсутствие двойного изменения прогресса. Повторить проверку после обновления приложения; дождаться следующей реальной ежедневной выдачи.

### 10. Эксплуатация и пилот базовой версии

**Сделать:** автоматические согласованные резервные копии SQLite и media, копию вне приложения, проверку восстановления и инструкцию отката. Контролировать работу планировщика и задержки доставки, а не только доступность панели. Провести несколько реальных ежедневных циклов на небольшой группе и исправить обнаруженные проблемы.

**Результат:** подтверждённая регулярная работа без ИИ и воспроизводимое восстановление данных. Резервирование и минимальный контроль ошибок должны работать до подключения реальных учеников.

**Проверка:** восстановление на отдельной установке, сбой процесса, временная недоступность Telegram, переполнение/недоступность хранилища, сохранность очереди и истории после обновления. Дубли сообщений при неопределённом результате Telegram допустимы; повторное начисление прогресса — нет.

### 11. ИИ-проверка кода и обратная связь

**Сделать:** подключаемую реализацию интерфейса проверки, отдельный тип задания с критериями оценки кода и текстовый фидбек. Провайдер и модель задаются конфигурацией; на этом этапе код ученика анализируется без исполнения.

Сначала сравнить результаты ИИ с оценками учителя на фиксированном наборе правильных, неправильных и частичных решений. До прохождения этой проверки ИИ работает в пробном режиме и не меняет расписание.

**Результат:** отдельный проверенный режим оценки решений с объяснением ошибок.

**Проверка:** корректность оценки на подготовленном наборе, тайм-ауты, недоступность провайдера и некорректный формат результата. Сбой ИИ не считается ошибкой ученика.

### 12. Сократовский диалог

**Сделать:** отдельный режим задания с подсказками и историей диалога. Подсказки не раскрывают готовый ответ; ученик отдельно отправляет окончательное решение.

Получение помощи помечается в попытке. Самостоятельный верный ответ продвигает интервал; решение с подсказками назначает повторение через день. Кнопка «Не знаю» завершает попытку как неуспешную.

**Результат:** бот помогает дойти до решения, сохраняя различие между самостоятельным выполнением и выполнением с помощью.

**Проверка:** несколько подсказок, финальное решение, отказ от продолжения, перезапуск посреди диалога и попытки заставить ИИ раскрыть эталон.

## Основные интерфейсы и критерий готовности

Прикладной слой предоставляет операции регистрации ученика, назначения темы, получения очередного задания, принятия ответа и запуска ежедневной выдачи.

Проверяющий модуль возвращает результат **«верно / неверно / проверка недоступна»** и необязательный фидбек. Только принятый учебной сессией итог меняет расписание. ИИ и Telegram не обновляют прогресс напрямую.

Каждая итерация завершается рабочей демонстрацией, проверками своей логики и обновлённой инструкцией запуска. Новые системы добавляются тогда, когда начинается соответствующий этап; заранее закладываются только границы модулей.

За пределами этого роадмапа: несколько учителей, собственный фронтенд, платежи, рейтинги, геймификация, автоматический сбор заданий и исполнение присланного кода.
