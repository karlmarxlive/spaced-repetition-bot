# Роадмап бота для подготовки к ЕГЭ по информатике

Братан, строим проект небольшими законченными итерациями: у каждой есть рабочий результат и сценарий проверки. Первая полноценная версия заканчивается на этапе 7. Затем добавляем ИИ, проверяем его локально и только последним этапом переносим бота на сервер.

## Основа проекта

**Стек:** Python, Django со стандартной админ-панелью, SQLite, aiogram для Telegram. Локально работают три процесса: веб-панель, бот через long polling и планировщик. Они используют одну базу данных.

**Архитектура:** модульный монолит — один проект с отдельными системами и явными интерфейсами между ними. Микросервисы, Redis, Celery и отдельный фронтенд на старте не нужны.

| Модуль | Ответственность |
|---|---|
| Пользователи | Учитель, ученики, приглашения и привязка Telegram |
| Учебный материал | Курс, темы, задания, эталонные ответы и вложения |
| Повторения | Прогресс по темам и расчёт следующей даты |
| Учебная сессия | Очередь заданий, текущий вопрос, обработка попыток |
| Проверка | Сначала сравнение с эталоном, позднее проверка через ИИ |
| Доставка | Отправка сообщений, повторные попытки при сбоях |
| Интерфейсы | Telegram для ученика, Django Admin для учителя |

Telegram-обработчики и формы админки вызывают общие прикладные операции. Правила повторения и проверки не размещаем непосредственно в обработчиках кнопок.

## Правила первой версии

- Один учитель, один курс, несколько учеников. Учитель входит в веб-панель; ученик регистрируется через приглашение в Telegram.
- Прогресс хранится отдельно для каждой пары **«ученик — тема»**. Учитель отмечает темы, которые ученик уже прошёл.
- При включении темы первое задание становится доступным в ближайшую ежедневную выдачу.
- За один цикл выдаётся по одному заданию на каждую тему, срок повторения которой наступил. В каждый момент у ученика только одно активное задание.
- После верных ответов интервалы составляют **3 → 7 → 14 → 30 → 60 → 60… дней**. Любая ошибка назначает повторение через **1 день**; верный ответ после этого снова назначает **3 дня**.
- Интервал отсчитывается от календарной даты принятого ответа в `Europe/Moscow`. Выдача начинается в заданное учителем время; первоначальное значение — **18:00**.
- Неверный ответ завершает попытку. Бот сообщает об ошибке, **не раскрывает эталон**, затем отправляет следующее задание.
- Если ученик не ответил, текущее задание сохраняется, расписание темы не меняется. Следующая ежедневная выдача не создаёт второе активное задание.
- Просроченные темы не накапливают отдельные задания за каждый пропущенный день: одна тема занимает одно место в очереди.
- Задания внутри темы проходят по кругу в устойчивом порядке. При единственном задании оно повторяется.
- Отключение темы прекращает её выдачу и отменяет незавершённое задание по ней. Повторное включение начинает цикл заново; история попыток сохраняется.

## Итерации разработки

### 1. Каркас и локальный запуск

**Сделать:** структуру модулей, настройки окружения, миграции, тестовый запуск Django и бота, журналирование ошибок. Секреты хранить вне репозитория, подготовить пример конфигурации и инструкцию запуска.

**Результат:** веб-панель открывается локально, бот отвечает на `/start`.

**Проверка:** проект запускается по инструкции с пустой базой; отсутствие токена вызывает понятную ошибку. Добавление данных не требуется для запуска тестов.

### 2. Курс и банк заданий

**Сделать:** модели курса, тем и заданий; управление ими через админку. Задание содержит текст условия, несколько необязательных вложений (картинок или файлов), эталон короткого ответа и признак активности. Вложения хранятся локально отдельными записями `TaskAttachment` и скачиваются через защищённый маршрут админки. Поддержка нескольких вложений реализована; миграция сохраняет прежние ссылки без перемещения файлов.

**Результат:** учитель может самостоятельно наполнить небольшой учебный банк.

**Проверка:** создать, отредактировать и отключить задание; проверить сохранение вложений. Не разрешать активировать задание без условия или ответа. Используемые задания архивировать, сохраняя историю.

### 3. Регистрация и пройденные темы

**Сделать:** одноразовые ссылки-приглашения, профиль ученика и отметки пройденных тем в админке. Telegram ID служит постоянным идентификатором; имя пользователя — только отображаемым полем.

**Результат:** ученик открывает приглашение, регистрируется, учитель назначает ему темы.

**Проверка:** повторный `/start` не создаёт дубликат; использованное приглашение нельзя применить для другого аккаунта; ученик не получает доступ к функциям учителя.

### 4. Движок интервального повторения

**Сделать:** прогресс темы, ступень интервала, дату следующего повторения и расчёт переходов. Передавать текущее время в расчёты явно, чтобы тестировать месяцы обучения за секунды.

**Результат:** расписание полностью работает без Telegram.

**Проверка:** вся последовательность до повторных 60 дней; ошибка на любой ступени; несколько ошибок подряд; независимость учеников и тем; ответы после полуночи; отключение и повторное включение темы.

### 5. Полный учебный цикл по команде

**Сделать:** команду `/review`, очередь наступивших тем, отправку условия с вложением, приём текстового ответа и автоматический переход к следующему заданию. После очереди — краткий итог занятия.

Для коротких ответов удалять только пробелы по краям; затем сравнивать с эталоном точно. Регистр, внутренние пробелы и числовые форматы автоматически не преобразовывать.

**Результат:** основной сценарий уже можно пройти вручную от начала до конца.

**Проверка:** правильный и неправильный ответ, пустая очередь, тема без активных заданий, повторная команда во время вопроса. Команды и неподдерживаемые вложения не засчитываются как неправильный ответ.

### 6. Автоматическая ежедневная выдача

**Сделать:** общее время выдачи в админке, отдельный планировщик и сохранение очереди в базе. `/review` оставить для ручного запуска и продолжения.

При открытом задании новые наступившие темы добавляются в очередь без дубликатов. После простоя компьютера бот подхватывает пропущенную выдачу, когда запускается после заданного времени.

**Результат:** бот сам начинает повторение и продолжает его после ответов.

**Проверка:** наступление времени, повторный проход планировщика, пропущенный день, несколько просроченных тем, незавершённая предыдущая сессия. Тесты используют управляемое время вместо реального ожидания.

### 7. Надёжность и завершение базовой версии

**Сделать:** атомарное сохранение попытки и изменения расписания, защиту от повторной обработки Telegram-событий, сохранение состояния исходящих сообщений и повторную отправку при временных ошибках.

В админку добавить историю попыток, даты следующих повторений, активное задание и ошибки доставки. Сохранять снимок условия и эталона для попытки, чтобы последующее редактирование банка не меняло её смысл.

**Результат:** рабочая локальная версия, пригодная для тестирования с учениками.

**Проверка:** перезапуск до и после ответа, временная потеря сети, блокировка бота учеником, быстрые повторные сообщения, изменение задания во время сессии. Повторная обработка не должна дважды менять прогресс.

При неопределённом результате отправки Telegram возможен повтор сообщения; он должен ссылаться на то же задание и не создавать новую попытку.

### 8. ИИ-проверка кода и обратная связь

**Сделать:** подключаемую реализацию интерфейса проверки, отдельный тип задания с критериями оценки кода и текстовый фидбек. Провайдер и модель задаются конфигурацией; на этом этапе код ученика анализируется без исполнения.

Сначала сравнить результаты ИИ с оценками учителя на фиксированном наборе правильных, неправильных и частичных решений. До прохождения этой проверки ИИ работает в пробном режиме и не меняет расписание.

**Результат:** отдельный проверенный режим оценки решений с объяснением ошибок.

**Проверка:** корректность оценки на подготовленном наборе, тайм-ауты, недоступность провайдера и некорректный формат результата. Сбой ИИ не считается ошибкой ученика.

### 9. Сократовский диалог

**Сделать:** отдельный режим задания с подсказками и историей диалога. Подсказки не раскрывают готовый ответ; ученик отдельно отправляет окончательное решение.

Получение помощи помечается в попытке. Самостоятельный верный ответ продвигает интервал; решение с подсказками назначает повторение через день. Кнопка «Не знаю» завершает попытку как неуспешную.

**Результат:** бот помогает дойти до решения, сохраняя различие между самостоятельным выполнением и выполнением с помощью.

**Проверка:** несколько подсказок, финальное решение, отказ от продолжения, перезапуск посреди диалога и попытки заставить ИИ раскрыть эталон.

### 10. Локальный пилот и подготовка эксплуатации

**Сделать:** пройти несколько учебных циклов на тестовой группе, исправить найденные проблемы, добавить резервное копирование базы и вложений, проверить восстановление. Подготовить команды запуска, остановки и обновления.

**Результат:** воспроизводимая локальная сборка и подтверждённое восстановление данных.

**Проверка:** ускоренный многодневный сценарий, реальные Telegram-ответы, восстановление на чистой локальной установке. Пока компьютер выключен, автоматическая доставка недоступна.

### 11. Перенос на сервер

**Сделать:** развернуть проверенную сборку, перенести базу и вложения, настроить автозапуск процессов, HTTPS и доступ к панели учителя, резервные копии и контроль ошибок.

На первом сервере сохранить SQLite и long polling. PostgreSQL и webhook добавлять отдельными задачами при появлении конкретной необходимости.

**Результат:** бот работает независимо от локального компьютера.

**Проверка:** перезагрузка сервера, регистрация, ежедневная выдача, ответ и обновление расписания, ИИ-режимы и восстановление резервной копии. Перед запуском серверного экземпляра остановить локальный бот.

## Основные интерфейсы и критерий готовности

Прикладной слой предоставляет операции регистрации ученика, назначения темы, получения очередного задания, принятия ответа и запуска ежедневной выдачи.

Проверяющий модуль возвращает результат **«верно / неверно / проверка недоступна»** и необязательный фидбек. Только принятый учебной сессией итог меняет расписание. ИИ и Telegram не обновляют прогресс напрямую.

Каждая итерация завершается рабочей демонстрацией, проверками своей логики и обновлённой инструкцией запуска. Новые системы добавляются тогда, когда начинается соответствующий этап; заранее закладываются только границы модулей.

За пределами этого роадмапа: несколько учителей, собственный фронтенд, платежи, рейтинги, геймификация, автоматический сбор заданий и исполнение присланного кода.
