# Роадмап бота для подготовки к ЕГЭ по информатике

Строим проект небольшими законченными итерациями: у каждой есть рабочий результат и сценарий проверки. Базовый учебный цикл (этапы 1–7) и серверная сборка (этап 8) реализованы. Текущий этап — 9: приёмка и запуск на Amvera. ИИ-проверку и помощь в решении добавляем после запуска и стабилизации базовой версии.

План пересмотрен 6 октября 2026 года. Решение: на сервере начать с чистой базы, локальные данные не переносить; первая группа — до 10 учеников. Состояние сервера и порядок запуска — в [инструкции по эксплуатации](docs/amvera-operations.md#текущее-состояние-сервера), ручная приёмка — в [чек-листе](docs/acceptance-checklist.md).

## Основа проекта

**Стек:** Python, Django со стандартной админ-панелью, SQLite, aiogram для Telegram. Работают три процесса: веб-панель, бот через long polling и планировщик ежедневной выдачи. Они используют одну базу данных; на сервере их запускает общий управляющий процесс в одном Docker-контейнере.

**Архитектура:** модульный монолит — один проект с отдельными системами и явными интерфейсами между ними. Микросервисы, Redis, Celery и отдельный фронтенд на старте не нужны.

| Модуль | Ответственность |
|---|---|
| Пользователи | Учитель, ученики, приглашения и привязка Telegram |
| Учебный материал | Курс, темы, задания, эталонные ответы и вложения |
| Повторения | Прогресс по темам и расчёт следующей даты |
| Учебная сессия | Очередь заданий, текущий вопрос, обработка попыток |
| Проверка | Сначала сравнение с эталоном, позднее проверка через ИИ |
| Доставка | Отправка сообщений, повторные попытки при сбоях |
| Интерфейсы | Telegram для ученика, Django Admin для учителя |

Telegram-обработчики и формы админки вызывают общие прикладные операции. Правила повторения и проверки не размещаем непосредственно в обработчиках кнопок.

## Правила первой версии

- Один учитель, один курс, несколько учеников. Учитель входит в веб-панель; ученик регистрируется через приглашение в Telegram.
- Прогресс хранится отдельно для каждой пары **«ученик — тема»**. Учитель отмечает темы, которые ученик уже прошёл.
- При включении темы первое задание становится доступным в ближайшую ежедневную выдачу.
- За один цикл выдаётся по одному заданию на каждую тему, срок повторения которой наступил. В каждый момент у ученика только одно активное задание.
- После верных ответов интервалы составляют **1 → 3 → 7 → 14 → 30 → 60 → 60… дней** (согласовано 25.09.2026). Любая ошибка сбрасывает ступень на 0 и назначает повторение через **1 день**; следующий верный ответ даёт ступень 1 и **1 день**.
- Интервал отсчитывается от календарной даты принятого ответа в `Europe/Moscow`. Выдача начинается в заданное учителем время; первоначальное значение — **18:00**.
- Неверный ответ завершает попытку. Бот сообщает об ошибке, **не раскрывает эталон**, затем отправляет следующее задание.
- Если ученик не ответил, текущее задание сохраняется, расписание темы не меняется. Следующая ежедневная выдача не создаёт второе активное задание.
- Просроченные темы не накапливают отдельные задания за каждый пропущенный день: одна тема занимает одно место в очереди.
- Задания внутри темы проходят по кругу в устойчивом порядке. При единственном задании оно повторяется.
- Отключение темы прекращает её выдачу и отменяет незавершённое задание по ней. Повторное включение начинает цикл заново; история попыток сохраняется.
- При открытии задания сохраняется снимок условия, эталона и вложений. Изменение банка заданий не влияет на открытую попытку и историю. Используемые задания не удаляются, а деактивируются.
- Ответ — короткий текст, сравниваемый с эталоном после удаления пробелов по краям. Команды и вложения не считаются ответом и не меняют прогресс.
- Тема, включённая после состоявшейся ежедневной выдачи, попадает в следующую; `/review` позволяет начать её сразу.
- При неопределённом результате отправки сообщение может повториться; учебный результат и прогресс повторно не меняются.
- Учитель видит прогресс и историю отдельно по каждому ученику. Общей статистики по всем ученикам нет.

## Итерации разработки

### 1–8. Базовая версия и серверная сборка — реализовано

| Этап | Результат |
|---|---|
| 1. Каркас | Модули, настройки окружения, журналирование без секретов, автономные тесты, запуск панели и бота. |
| 2. Банк заданий | Курсы, темы, задания с эталонами и несколькими вложениями, защищённое скачивание через админку. |
| 3. Регистрация | Одноразовые приглашения; Telegram ID — постоянный идентификатор ученика, имя пользователя — только отображаемое поле; назначение пройденных тем в карточке. |
| 4. Повторения | Прогресс по каждой назначенной теме, ступени и даты повторения. Время передаётся в расчёты явно, что позволяет тестировать месяцы обучения за секунды. |
| 5. Занятие по команде | `/review`, очередь наступивших тем, снимки заданий, проверка по эталону, итог занятия. |
| 6. Ежедневная выдача | Время выдачи в админке, отдельный планировщик с проходом каждые 2 секунды, постоянная очередь, не больше одной выдачи на ученика в московские сутки. |
| 7. Надёжность | Журнал Telegram-событий и очередь исходящих сообщений с повторами; ответ принимается только на доставленный вопрос; персональная статистика ученика в админке. |
| 8. Серверная сборка | Docker и `amvera.yml`, серверные настройки Django, Gunicorn и WhiteNoise, управляющий процесс, резервирование с внешним экспортом, проверки состояния. Автономные и контейнерные проверки пройдены. |

Реальная работа с Telegram и смена календарных суток автономными тестами не подтверждаются: их проверяет ручная приёмка этапа 9.

### 9. Приёмка и первый запуск на Amvera

**Статус:** в работе. Приложение создано на Amvera в режиме первоначальной настройки, учитель создан; рабочий режим не включён. Актуальное состояние и оставшиеся шаги — в [инструкции по эксплуатации](docs/amvera-operations.md#текущее-состояние-сервера).

**Сделать:** пройти ручную приёмку по [чек-листу](docs/acceptance-checklist.md) на отдельной базе и отдельном тестовом боте. Настроить на Amvera секреты, HTTPS, хранилище, контроль состояния и внешний экспорт резервных копий: без него рабочий режим не запускается. Инициализировать чистую серверную базу, создать учителя и заполнить учебный банк; локальную базу и вложения не переносить. Первая группа — до 10 учеников. Перед запуском рабочего polling остановить локальный экземпляр, проверить `getMe` и отсутствие webhook; накопленные updates не удалять. Проверить отсутствие одновременно работающих экземпляров при обновлении Amvera.

**Результат:** учитель управляет курсом через HTTPS, бот ежедневно выдаёт задания, принимает ответы и сохраняет расписание независимо от локального компьютера.

**Проверка:** приглашение, назначение темы, автоматическая выдача по московскому времени, верный/неверный ответ, итог, продолжение после перезапуска, реальные вложения, блокировка бота и восстановление, отсутствие двойного изменения прогресса. Замерить память трёх процессов и при необходимости сменить тариф. Повторить проверку после обновления приложения; дождаться следующей реальной ежедневной выдачи.

### 10. Эксплуатация и пилот базовой версии

**Сделать:** подтвердить в реальной работе резервирование, внешнюю копию, восстановление и откат, реализованные на этапе 8. Контролировать работу планировщика и задержки доставки, а не только доступность панели. Провести несколько реальных ежедневных циклов на небольшой группе и исправить обнаруженные проблемы.

**Результат:** подтверждённая регулярная работа без ИИ и воспроизводимое восстановление данных. Резервирование и минимальный контроль ошибок должны работать до подключения реальных учеников.

**Проверка:** минимум две последовательные ежедневные выдачи без ручного `/review`; восстановление на отдельной установке без параллельного рабочего polling; сбой процесса, временная недоступность Telegram, переполнение/недоступность хранилища, сохранность очереди и истории после обновления. Дубли сообщений при неопределённом результате Telegram допустимы; повторное начисление прогресса — нет.

### 11. ИИ-проверка кода и обратная связь

**Сделать:** подключаемую реализацию интерфейса проверки, отдельный тип задания с критериями оценки кода и текстовый фидбек. Провайдер и модель задаются конфигурацией; на этом этапе код ученика анализируется без исполнения.

Сначала сравнить результаты ИИ с оценками учителя на фиксированном наборе правильных, неправильных и частичных решений. До прохождения этой проверки ИИ работает в пробном режиме и не меняет расписание.

**Результат:** отдельный проверенный режим оценки решений с объяснением ошибок.

**Проверка:** корректность оценки на подготовленном наборе, тайм-ауты, недоступность провайдера и некорректный формат результата. Сбой ИИ не считается ошибкой ученика.

### 12. Сократовский диалог

**Сделать:** отдельный режим задания с подсказками и историей диалога. Подсказки не раскрывают готовый ответ; ученик отдельно отправляет окончательное решение.

Получение помощи помечается в попытке. Самостоятельный верный ответ продвигает интервал; решение с подсказками назначает повторение через день. Кнопка «Не знаю» завершает попытку как неуспешную.

**Результат:** бот помогает дойти до решения, сохраняя различие между самостоятельным выполнением и выполнением с помощью.

**Проверка:** несколько подсказок, финальное решение, отказ от продолжения, перезапуск посреди диалога и попытки заставить ИИ раскрыть эталон.

## Основные интерфейсы и критерий готовности

Прикладной слой предоставляет операции регистрации ученика, назначения темы, получения очередного задания, принятия ответа и запуска ежедневной выдачи.

Проверяющий модуль возвращает результат **«верно / неверно / проверка недоступна»** и необязательный фидбек. Только принятый учебной сессией итог меняет расписание. ИИ и Telegram не обновляют прогресс напрямую.

Каждая итерация завершается рабочей демонстрацией, проверками своей логики и обновлённой инструкцией запуска. Новые системы добавляются тогда, когда начинается соответствующий этап; заранее закладываются только границы модулей.

За пределами этого роадмапа: несколько учителей, собственный фронтенд, платежи, рейтинги, геймификация, автоматический сбор заданий и исполнение присланного кода.
