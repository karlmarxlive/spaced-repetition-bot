# Инструкции для агента

## Проект

- Telegram-бот для подготовки к ЕГЭ по информатике с интервальными повторениями.
- Python 3.14, Django, aiogram, SQLite; модульный монолит.
- `modules/` — учебная логика и модели, `bot/` — Telegram, `config/` — настройки, `deploy/` — серверный запуск, `tests/` — проверки.
- Установка и локальный запуск описаны в [README.md](README.md), эксплуатация — в [docs/amvera-operations.md](docs/amvera-operations.md).
- Актуальное состояние сервера проверяй через Amvera, а не выводи из старого отчёта.

## Принципы изменений

- Выполняй только запрошенную задачу и необходимые для неё изменения.
- Выбирай минимальное по объёму корректное решение с минимальной дополнительной сложностью в рамках существующей архитектуры.
- Исправляй причину ошибки; не скрывай её подавлением исключений, заглушками или обходными путями.
- Сохраняй существующее поведение за пределами задачи.
- Не добавляй функции, настройки и расширяемость «на будущее».
- Используй существующие функции и подходы, если они подходят задаче.
- Вводи новую абстракцию только когда она упрощает текущую задачу. Небольшое локальное дублирование допустимо, если обобщение сложнее.
- Не добавляй зависимости без конкретной необходимости.
- Не совмещай задачу с попутным рефакторингом, переименованиями, форматированием и обновлением зависимостей.
- Сохраняй форматирование и окончания строк в затронутых файлах; избегай перезаписи всего файла ради локальной правки.
- Не отменяй и не перезаписывай чужие незавершённые изменения.
- Проверяй итоговый diff: каждое изменение должно объясняться задачей.

## Ограничения проекта

- Сохраняй транзакционность учебных операций, защиту от повторной обработки событий, историю попыток и прогресс учеников.
- Изменения доставки не должны приводить к повторному зачёту ответа или потере очереди исходящих сообщений.
- При изменении схемы учитывай существующие SQLite-триггеры. Добавляй новые миграции вместо переписывания применённых.
- Рабочие `.env`, SQLite и `media/` не используй для автоматических тестов и не перезаписывай ради настройки окружения.
- Для одного Telegram-токена должен работать только один polling-процесс; планировщик также запускается в одном экземпляре.

## Проверки

- В WSL используй `.venv-wsl/bin/python`, в Windows — `.venv\Scripts\python.exe`. Зависимости устанавливай из `requirements.txt`.
- Проверяй изменённое поведение. При исправлении ошибки добавляй регрессионный тест, когда он надёжно воспроизводит проблему.
- В итоговом ответе кратко сообщай, что изменено, что проверено и какие проверки выполнить не удалось.

## Amvera и подключения

- Когда пользователь просит изменить проект, проверить логи или работу приложения, пересобрать проект либо добавить секреты, в начале работы попытайся проверить доступность Amvera MCP.
- Адрес MCP: `https://openmcp.msk0.amvera.ru/mcp`. Токен авторизации бери из `AMVERA_MCP_TOKEN` в окружении; если он настроен через локальный dotenv-файл, читай только нужную переменную без вывода её значения.
- Используй настроенное MCP-подключение, если оно доступно. Если его нет, попытайся выполнить авторизованную MCP-инициализацию и получить список инструментов через HTTPS. Обычный HTTP-ответ сам по себе не подтверждает работоспособность MCP.
- Проверка доступности должна быть только читающей, с ограниченным тайм-аутом. Не запускай пересборку и не меняй секреты ради проверки соединения.
- Не выводи токен, заголовки авторизации и значения секретов в чат, логи или команды. Не сохраняй их в репозитории; передавай авторизацию внутри клиента из переменной окружения.
- Если токена нет или MCP недоступен, кратко сообщи причину без секретных данных и продолжай независимую локальную работу. Не утверждай, что серверная проверка выполнена.
- Через доступный MCP проверяй относящиеся к задаче состояние приложения и логи; пересборку и изменение секретов выполняй в рамках запроса пользователя. Наличие токена само по себе не разрешает деплой.
- Перед изменениями в Amvera установи целевое приложение и окружение. После операции проверь результат: статус сборки и приложения, необходимые логи или наличие имён секретов без чтения их значений.
- Актуальные Git remote проверяй через `git remote -v`. Remote `amvera` предназначен для Amvera; учитывай возможное различие историй и не используй force push без явного запроса.
